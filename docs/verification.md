# 真机验收清单

> 当前状态：**未验证**。线格式本身是社区逆向（见 docs/protocol.md），
> 本清单里前 5 项同时是「协议未确认项」的唯一裁决手段。

## 环境

| 项 | 值 |
|---|---|
| 头显 | Bigscreen Beyond 2e（记录固件版本） |
| 来源应用 | Bigscreen 官方「Beyond Eyetracking」应用（记录版本号） |
| 系统 | Windows 10 / 11 x64 |
| 宿主 | FaceGaze Bridge（记录版本号） |

## 步骤

- [ ] 按官方指引安装并登记眼追（Enrollment）
- [ ] 在眼追应用里**勾选 VRCFT 接收**（本模块读的就是这条输出）
- [ ] 完全退出 VRCFaceTracking（与本模块抢同一共享内存机制）
- [ ] FGB「模块库 → 原生模块」安装 `beyond-<版本>.zip`
- [ ] 「模块」页把 Bigscreen Beyond 设为启动，角色给 `eyes` 与 `gaze`，重启引擎
- [ ] 戴上头显，模块卡片显示活跃

## 观察项（协议未确认项的裁决）

- [ ] 注视正前方远处 → 日志/状态页里 `gaze_dir.z` 为**负**（-Z 前假设成立；为正就反号，见 protocol.md 待办 1）
- [ ] 向左/右/上/下看 → 方向分量跟随且极化正确
- [ ] 眨眼 → 对应眼 `openness` 下降并可恢复到 1（旧版应用恒 1 = 闭眼量未写入）
- [ ] 摘下头显 / 停止追踪 → 卡片给出「IsValid != 1」或断流提示，且**输出不冻结在最后姿态假装有效**
- [ ] 来源应用退出后再启动 → 模块 1 秒级重开映射并恢复
- [ ] 记录 Confidence 实际取值范围（恒 1？随质量变化？0..1 还是别的量纲）
- [ ] 记录 Timestamp 与系统 UTC 毫秒的差值（判定基准时钟）

## 排错提示核对

- [ ] 未启动眼追应用时，模块卡片报错包含映射名与「VRCFT 接收」指引
